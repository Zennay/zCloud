# GitHub Actions legacy command no-new-debt gate — 15 October 2026

**Scope:** additive GitHub-hosted, source-only ratchet for [zCloud #633](https://github.com/Zennay/zCloud/issues/633). The new branch owns only four unique new paths: this document, a scanner, a temporary-Git test suite and a read-only PR workflow. No pre-existing workflows, live runners, release scripts, workers, SQLite, Firefox or VPS resources are modified.

## Why
GitHub Actions' deprecated workflow logging commands `::set-env`, `::add-path`, `::set-output` and `::save-state` are unsafe legacy patterns. Re-enabling `ACTIONS_ALLOW_UNSECURE_COMMANDS` is particularly risky. Even if old workflow blobs cannot be remediated during another owner's live-workflow window, adding or editing workflows should not create *new* debt.

## Behavior and tests
- Against an immutable ancestor `BASE..HEAD`, inspect only **added/modified regular Git blobs** in `.github/workflows/*.yml|yaml`, `.github/actions/**/action.yml|yaml` and the changed **local Action implementations** under `.github/actions/**`: JavaScript/TypeScript (`.js`, `.cjs`, `.mjs`, `.ts`), shell (`.sh`, `.bash`, `.ps1`, `.zsh`), Windows batch (`.cmd`, `.bat`), Python (`.py`), Ruby/Perl (`.rb`, `.pl`), `Dockerfile`/`Containerfile`, and `package.json` lifecycle scripts. Execute-bit `100755` blobs are checked even without extensions; common extensionless entrypoints `entrypoint`, `run`, `start`, `bootstrap`, `Makefile`, and `GNUmakefile` are also checked when newly edited.
- Reject changed workflow/action source containing legacy command names, any case-variant of `ACTIONS_ALLOW_UNSECURE_COMMANDS`, malformed or multiply nested YAML scalar Unicode escapes, hidden or malformed Unicode/ASCII control characters (literal and decoded), invalid UTF-8, oversized blobs, symlinked roots/files, malformed refs or disconnected source trees. Ordinary CRLF/LF and tabs remain allowed, but an embedded NUL, ESC, DEL or other ambiguous control byte fails closed. Reject control-bearing Git pathnames within the changed workflow/action roots.
- **Fail closed on newly introduced Gitlinks (submodules) or symlinks anywhere beneath `.github/actions/` or `.github/workflows/`, even without a changed `action.yml`.** These opaque references cannot be established as trusted by scanning action metadata only. Existing unchanged links are not retroactively approved. A new ordinary text file under `.github/actions/` is permitted when it has no restricted metadata; this is *not* a certification of arbitrary action scripts.
- Unchanged historical blobs are *grandfathered, not certified safe*. Files newly edited after this gate is installed are subject to review. The lexical detector is intentionally conservative and may reject comments/examples, while dynamically assembled commands may evade it; this is one defense layer, not a YAML, shell or Actions security parser.
- Test with actual temporary Git repositories, including safe/adversarial workflows, symlinks, gitlink/submodule entries, deleted files, nested Action implementation scripts, Dockerfile/Containerfile, root and nested composite Actions, historical grandfathering, invalid Unicode scalars and oversized or nested escapes.
- Every Git command has its own monotonic 15-second deadline and actively capped stdout; a separate context-local, always-reset **120-second total scan deadline** bounds multi-file or slow-Git abuse. Expired budgets deny *before* launching further Git subprocesses. On failed Git observations the **entire spawned process group** is killed, including when the direct Git process has already exited but a descendant inherited stdout. The direct child is always reaped. The output is advisory source proof, not independently enforced branch protection.
- Legacy commands split across shell backslash-newline continuations (including CRLF and encoded backslashes), POSIX backslash-escaped literal command tokens (including mixed caret escapes), Windows CMD caret-escaped tokens, or PowerShell backtick-escaped tokens and line continuations are reconstructed conservatively before checking. Ordinary harmless continuations remain accepted. These are source-level safeguards: shell interpolation, scripts outside `.github/actions/`, imported libraries, third-party remote actions, binary action payloads, non-executable extensionless data files, aliases and dynamically generated commands are not a fully analyzed execution graph. The CMD caret and PowerShell backtick reconstruction deliberately scan broad source strings and can deny comments or examples; dynamic expressions and external scripts remain explicitly out of scope.
- The dedicated PR job uses GitHub-hosted `ubuntu-latest`, `contents: read`, exact SHA-pinned checkout and `persist-credentials: false`. Remote main and PR head must match PR event SHA **before and after** tests. It cannot run a privileged workflow or approve itself.

## Deployment contract
No PR-controlled check grants trusted merge approval, branch protection, owner consent, VPS/runner acceptance or production-dispatch authority. Keep [#922](https://github.com/Zennay/zCloud/issues/922), [#1326](https://github.com/Zennay/zCloud/issues/1326), [#1447](https://github.com/Zennay/zCloud/issues/1447), and #580/PWQ-41/#1089 independently gated. After exact-head GitHub-hosted CI is green, the PR may be marked ready for independent review; this is **not** merge/deployment approval. Do not merge/deploy automatically.
