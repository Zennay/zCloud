# Source-only CI artifact upload exposure gate — 15 October 2026

Issue: #633 (self-hosted workflow trust debt). Owner: separate deploy-ops file-disjoint source lane.

This new GitHub-hosted pull-request check rejects changed or new workflow YAML that advertises an upload-artifact action with a broad or secret-bearing path: repository root, recursive glob, shell/dynamic expression, traversal, .env, .ssh, credentials, secrets and token files. It also rejects a true or ambiguous include-hidden-files value; a missing path; duplicate upload parameters; YAML aliases; symlinked workflow blobs; malformed source identities; and non-ASCII workflow path ambiguity. Path inventory and source blobs are bounded. Git output is bounded **as bytes arrive** (not post-hoc), all Git reads use a monotonic deadline and an isolated process group; a failed read kills a stdout-holding descendant even when its direct Git wrapper already exited. The real-process regressions exercise both the malicious inherited-stdout case and a benign read. Existing unchanged workflows are grandfathered; they are **not** certified safe.

The checker uses exact SHA-bound Git source ancestry, an immutable checkout, read-only GitHub token permissions, independent GitHub-hosted runner, and origin/main/head source identity checked before and after regressions. The tests include a real temporary Git history and a symlink fixture. Only the four new files in this lane are owned. No existing runtime/control-plane/VPS/release workflow changes are permitted.


Follow-up security fixes on the same owner branch: inspect YAML-escaped action identities (`\\xNN`, `\\uNNNN`, `\\UNNNNNNNN`) and encoded double-quoted mapping keys **before** searching for the literal `upload-artifact` token. GitHub/YAML can decode these spellings into an upload step; failing to detect them creates a silent bypass. Reject single-file private key container formats (`.pem`, `.p12`, `.pfx`, `.jks`, `.keystore`, `.key`, `.asc`) and cloud credential roots (`.aws`, `.kube`, `.azure`, `.gnupg`, `.gcloud`) even when the path has no wildcard. Added corresponding negative fixtures and ordinary upload extension positive controls. This is intentionally conservative: a safe public certificate ending in `.pem` still needs explicit review instead of an automatic pass.


Follow-up on YAML mapping integrity: reject duplicate `with:` mappings in an upload step, even if the first contains an apparently safe `path`. A later mapping may override the first one in YAML parsers. Also reject nested option indentation instead of mistakenly treating a nested `path` as a top-level action input. A correctly indented sibling `if:` property remains valid. Regression tests include all three cases.


Expanded source coverage: **new/edited `.github/actions/**/action.yml` and `action.yaml` composite Action manifests** are scanned for unsafe upload-artifact steps alongside workflow files. A workflow can call a local composite Action whose manifest contains its own artifact upload step; looking only at `.github/workflows` misses that source. CI path triggers now include `.github/actions/**`. Ordinary non-manifest files under that root are not blindly treated as YAML entrypoints; their indirect effects and imported scripts remain outside this bounded check. New real Git tests prove a sensitive `.pem` upload in a changed composite manifest is rejected and a non-manifest shell edit is not misclassified as a YAML action.

Additional source-boundary remediation (15 October): ancestry is now checked through the **same 10-second bounded, process-group-cleanup, no-Git-object-replacements reader** as all other Git metadata, rather than an independent Git invocation with inherited replacement behavior. A real divergent Git-history fixture must deny untrusted bases. UTF-8 is retained for ordinary printable workflow comments, but C1 controls, invisible format/BiDi characters, surrogate values and Unicode line/paragraph separators are rejected before lexical YAML parsing; adversarial regressions cover each. Also reject new/modified **nonregular local Action entries** (symlinks and Gitlinks/submodule links) even when their filenames are not manifest YAML: otherwise an opaque Action path could be silently skipped while changed manifest files are checked. Real Git fixtures prove both symlink and Gitlink denial, without expanding into other workers' protected workflows.

The same Action-manifest rule now also covers root-level `actions/**/action.yml` and `actions/**/action.yaml` (not just `.github/actions/**`). These are valid locations for local composite Actions referenced by workflows. The GitHub-hosted path trigger includes `actions/**`. Real Git history demonstrates a newly introduced `actions/archive/action.yaml` that uploads a narrow credential-bearing filename is rejected, while the normal non-manifest source distinction is preserved. This expansion is still strictly **changed-only**, SHA-bound and non-authorizing.

Limitations: deliberately conservative lexical YAML screening, not a complete YAML or GitHub Actions evaluator. Dynamically imported actions, repository contents inside a nominally narrow artifact path, cross-step dataflow, renamed aliases with no literal upload-artifact token, and unchanged legacy workflow files are out of scope. False positives for ambiguous upload syntax are intentional; explicit review remains required. A PASS is source evidence only, never production safety, independence of approval, permission to merge, or privilege to release.

Manual local check (read-only): python3 -m unittest discover -s tests -p 'test_zcloud_artifact_upload_exposure_ratchet_20261015_w1.py'. The GitHub-hosted PR workflow calls the exact source checker with immutable base/head SHA, and rechecks the remote references after the tests.

Release boundary: protected-main #922, canonical runner proof #1326, existing writer locks #1447 and serialized #580/PWQ-41/#1089 remain separate independent gates. No runner/VPS/Firefox/SQLite/worker/queue modification, privileged workflow dispatch, merge, or production promotion is authorized here.
