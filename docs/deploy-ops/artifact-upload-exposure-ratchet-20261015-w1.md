# Source-only CI artifact upload exposure gate — 15 October 2026

Issue: #633 (self-hosted workflow trust debt). Owner: separate deploy-ops file-disjoint source lane.

This new GitHub-hosted pull-request check rejects changed or new workflow YAML that advertises an upload-artifact action with a broad or secret-bearing path: repository root, recursive glob, shell/dynamic expression, traversal, .env, .ssh, credentials, secrets and token files. It also rejects a true or ambiguous include-hidden-files value; a missing path; duplicate upload parameters; YAML aliases; symlinked workflow blobs; malformed source identities; and non-ASCII workflow path ambiguity. Path inventory and source blobs are bounded. Git output is bounded **as bytes arrive** (not post-hoc), all Git reads use a monotonic deadline and an isolated process group; a failed read kills a stdout-holding descendant even when its direct Git wrapper already exited. The real-process regressions exercise both the malicious inherited-stdout case and a benign read. Existing unchanged workflows are grandfathered; they are **not** certified safe.

The checker uses exact SHA-bound Git source ancestry, an immutable checkout, read-only GitHub token permissions, independent GitHub-hosted runner, and origin/main/head source identity checked before and after regressions. The tests include a real temporary Git history and a symlink fixture. Only the four new files in this lane are owned. No existing runtime/control-plane/VPS/release workflow changes are permitted.


Follow-up security fixes on the same owner branch: inspect YAML-escaped action identities (`\\xNN`, `\\uNNNN`, `\\UNNNNNNNN`) and encoded double-quoted mapping keys **before** searching for the literal `upload-artifact` token. GitHub/YAML can decode these spellings into an upload step; failing to detect them creates a silent bypass. Reject single-file private key container formats (`.pem`, `.p12`, `.pfx`, `.jks`, `.keystore`, `.key`, `.asc`) and cloud credential roots (`.aws`, `.kube`, `.azure`, `.gnupg`, `.gcloud`) even when the path has no wildcard. Added corresponding negative fixtures and ordinary upload extension positive controls. This is intentionally conservative: a safe public certificate ending in `.pem` still needs explicit review instead of an automatic pass.


Follow-up on YAML mapping integrity: reject duplicate `with:` mappings in an upload step, even if the first contains an apparently safe `path`. A later mapping may override the first one in YAML parsers. Also reject nested option indentation instead of mistakenly treating a nested `path` as a top-level action input. A correctly indented sibling `if:` property remains valid. Regression tests include all three cases.


Expanded source coverage: **new/edited `.github/actions/**/action.yml` and `action.yaml` composite Action manifests** are scanned for unsafe upload-artifact steps alongside workflow files. A workflow can call a local composite Action whose manifest contains its own artifact upload step; looking only at `.github/workflows` misses that source. The hosted PR admission runs unconditionally; .github/actions manifests are included in the source inventory. Ordinary non-manifest files under that root are not blindly treated as YAML entrypoints; their indirect effects and imported scripts remain outside this bounded check. New real Git tests prove a sensitive `.pem` upload in a changed composite manifest is rejected and a non-manifest shell edit is not misclassified as a YAML action.

Additional source-boundary remediation (15 October): ancestry is now checked through the **same 10-second bounded, process-group-cleanup, no-Git-object-replacements reader** as all other Git metadata, rather than an independent Git invocation with inherited replacement behavior. A real divergent Git-history fixture must deny untrusted bases. UTF-8 is retained for ordinary printable workflow comments, but C1 controls, invisible format/BiDi characters, surrogate values and Unicode line/paragraph separators are rejected before lexical YAML parsing; adversarial regressions cover each. Also reject new/modified **nonregular local Action entries** (symlinks and Gitlinks/submodule links) even when their filenames are not manifest YAML: otherwise an opaque Action path could be silently skipped while changed manifest files are checked. Real Git fixtures prove both symlink and Gitlink denial, without expanding into other workers' protected workflows.

The same Action-manifest rule now also covers root-level `actions/**/action.yml` and `actions/**/action.yaml` (not just `.github/actions/**`). These are valid locations for local composite Actions referenced by workflows. The hosted PR admission runs unconditionally and inspects manifests in actions/**. Real Git history demonstrates a newly introduced `actions/archive/action.yaml` that uploads a narrow credential-bearing filename is rejected, while the normal non-manifest source distinction is preserved. This expansion is still strictly **changed-only**, SHA-bound and non-authorizing.

**Action identity folding boundary (15 October):** GitHub/YAML can concatenate a double-quoted `uses` value across a backslash-newline boundary, so the literal `upload-artifact` string may never appear in the raw file even though the parsed Action reference resolves to that name. The scan now rejects ambiguous `uses:` scalars before the literal fast path: folded/block values, backslash continuations, YAML aliases/anchors/tags/flow containers, empty values and unterminated quoted strings. Explicit single- and double-quoted Actions and benign checkout references remain supported. Exact GitHub-hosted [focused run #38812572563](https://github.com/Zennay/zCloud/actions/runs/38812572563) passed **50/50 adversarial tests** on code/test HEAD `8f6c04c9d09d53e80270128a23bf22490fb1083a`. This historical run does **not** attest the subsequent documentation commit or full-suite release criteria. Source-only, non-authorizing, no live VPS changes.

**More narrow-file credential protections (15 October):** registry and cloud tools also store credentials in innocuously named JSON/XML files. The checker now denies any upload path containing a sensitive configuration directory (`.docker`, `.terraform`, `.npm`, `.m2`, `.config` in addition to existing cloud identity directories), or ending in `.netrc`, `.pypirc`, `.git-credentials`, `id_ed25519`, `id_ecdsa`, `id_dsa` or `gradle.properties`. Positive control fixtures allow ordinary build logs and reports without these protected paths. These are source-path heuristics only, not evidence that a permitted file's content is safe.

**Critical trust boundary:** PR-hosted checks use PR-branch workflow/script content until this guard can be merged and required under independently enforced protected-main policy. A privileged contributor could edit the guard itself, or disable its workflow, in their own PR. Hosted green checks therefore establish tests on an **exact source candidate**, not repository-wide enforcement. #922 must introduce strict required checks, independent approval and no bypass before any source-only gate can be considered enforceable. Neither this PR nor its CI can self-authorize merging or live deployment.

**Repository-wide local Action admission (15 October follow-up).** Relative local Actions can reside at arbitrary paths (including the repository root or tools/*), not just actions/* or .github/actions/*. Changed action.yml/action.yaml manifests are now inventoried from the full SHA-bound Git diff, regardless of directory; unrelated ordinary files are ignored prior to ASCII-only source-path admission. In particular, unrelated UTF-8 filenames are not falsely treated as workflow path errors. A directory-depth cap previously permitted silent skipping of nested Action manifests; this was removed, with a fixed maximum accepted path length of 512 and a bounded 100 kB changed-file inventory. Real Git regressions check deeply nested and arbitrary-root manifests, sensitive uploaded data, unrelated Unicode files and oversized paths. PR discovery itself is fail-closed on output/resource limits.

**Always-on hosted admission.** GitHub's pull_request paths filters can miss relevant files in sufficiently large changesets. The dedicated source-only gate now runs on *every* pull request (no paths filter), so it cannot be silently omitted by a changed-path discovery limit. The job is still GitHub-hosted with read-only token and exact base/head checks; source-only admission is not independent main enforcement. Tests assert the unconditional event trigger and non-persisted checkout credentials.

**Correct step mapping hierarchy (15 October).** Valid Actions upload steps may use either a bare list entry (- uses) or a named list entry (- name followed by a sibling uses). The scanner now recognises both instead of falsely denying named uploads. Only a with mapping at the step's sibling indentation counts as the Action input. Nested env/other mappings cannot spoof an apparently benign path. Negative tests cover unsafe named-step uploads and nested input spoofing. Positive fixtures preserve ordinary named upload steps. This bounded lexical checker does not replace a full YAML evaluator.

Limitations: deliberately conservative lexical YAML screening, not a complete YAML or GitHub Actions evaluator. Dynamically imported actions, repository contents inside a nominally narrow artifact path, cross-step dataflow, renamed aliases with no literal upload-artifact token, and unchanged legacy workflow files are out of scope. False positives for ambiguous upload syntax are intentional; explicit review remains required. A PASS is source evidence only, never production safety, independence of approval, permission to merge, or privilege to release.

Manual local check (read-only): python3 -m unittest discover -s tests -p 'test_zcloud_artifact_upload_exposure_ratchet_20261015_w1.py'. The GitHub-hosted PR workflow calls the exact source checker with immutable base/head SHA, and rechecks the remote references after the tests.

Release boundary: protected-main #922, canonical runner proof #1326, existing writer locks #1447 and serialized #580/PWQ-41/#1089 remain separate independent gates. No runner/VPS/Firefox/SQLite/worker/queue modification, privileged workflow dispatch, merge, or production promotion is authorized here.
