# Deploy-ops: workflow_run recursive redispatch ratchet (16 Oct 2026)

**Scope:** exclusively additive offline source admission for `workflow_run` jobs that invoke a second workflow with `gh workflow run`, `gh run rerun`, a POST to `/dispatches`, or REST rerun endpoints (`/actions/runs/{id}/rerun`, `/rerun-failed-jobs`, and `/actions/jobs/{id}/rerun`) or SDK dispatch/rerun methods (including option-order permutations, GitHub CLI field-implied POST, curl data-implied POST, wget --method/--post-data/--post-file POST and generic Octokit/github.request('POST /...') plus JavaScript fetch({method: POST})/axios.post and Python requests/httpx direct POST plus Session/Client/AsyncClient and common `session`/`client` POST calls or `request("POST", ...)` and PowerShell Invoke-RestMethod/Invoke-WebRequest and irm/iwr aliases with -Method POST, and arbitrarily many CLI global repository/hostname flags before any verb (within bounded 200-kB source), folded YAML shell commands, gh --input and curl form/data POST). Standard YAML `on :`/quoted `on` spaced-colon forms and variable-indentation event mappings, quoted or unquoted `run`/`uses` step keys, shell run steps and action list steps and ambiguous inline YAML trigger collections, duplicate inline/block event keys, aliases and merge mappings are explicitly denied before dispatch analysis. This addresses a separate event family from scheduled redispatch PR #1502. Tracked against #633 and #1216 without taking over either active owner.

- Candidate must descend from the immutable exact canonical main SHA. The checker checks bounded Git blob size metadata *before* reading content and reads exact Git tree object IDs, not mutable working-tree YAML, and declines symbolic links, gitlinks, oversized or undecodable manifest objects.
- It compares hashed executable command-line fingerprints **and multiplicity** inside each GitHub workflow path. Adding a second identical dispatch or changing a legacy dispatch target is detected. Identical existing findings are grandfathered as **legacy debt, not approved risk**. A newly introduced recursive dispatch finding fails admission.
- Run blocks are inspected; comments outside executable shell are not treated as commands. Static detection is deliberately non-exhaustive: dynamically constructed commands and helper scripts require manual review. Literal HTTP calls with arguments wrapped inside balanced parentheses are joined before matching. CLI commands are scanned to their physical newline, never truncated at 400 bytes; the immutable workflow blob itself is bounded to 200 kB. Do not infer that PASS authorizes merge or production.
- This branch only executes a GitHub-hosted, read-only, pinned-checkout `push` validation against its own immutable SHA and independently observed main. It does not use `pull_request` or `pull_request_target`, does not create new self-hosted jobs, and has no write permission.
- No merges, VPS dispatches, process restarts, queue/SQLite/Firefox/worker changes, direct-main changes, or production release authority. Live runner gap #1326, writer-lock collision #1447 and main protection #922 remain their separate owners.

Validation: `python3 -m unittest -v tests.test_zcloud_workflow_run_dispatch_gate_20261016_w34` then `python3 scripts/zcloud_workflow_run_dispatch_gate_20261016_w34.py --base <exact-main-sha> --head <exact-head-sha>`.
